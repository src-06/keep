Keep

keepTo

Specify multiple persistent storage locations to preserve state at.

Each attribute name is the path of a persistent storage root; the entry’s dirs and files are stored beneath it. Entries are independent: they may serve different users and apply different settings.

Type: attribute set of (submodule)

Default: { }

Example:

{
  keepTo."/keep/host_systems" = {
    # system-level, paths are absolute (username defaults to "root")
    enable = true;
    dirs = ["/var/lib/service"];
  };
  keepTo."/keep/user_data" = {
    # paths are relative to the user's home dir
    enable = true;
    username = "alice";
    dirs = ["Documents"];
  };
}

Declared by:

keepTo.<name>.dirs

Specify a list of dirs that should be preserved. The paths are interpreted as absolute paths for system entries (when username is root), or relative to the user’s home dir when username is set to another user.

Type: list of ((submodule) or string convertible to it)

Default: [ ]

Example:

[
  "/var/lib/someservice"
]

keepTo.<name>.dirs.*.inInitrd

Whether to prepare preservation of this dir in initrd.

Note: For most dirs there is no need to enable this option.

Important: Note that both owner and group for this dir need to be available in the initrd for permissions to be set correctly.

Type: boolean

Default: false

keepTo.<name>.dirs.*.method

Specify how this dir should be preserved.

  1. Either a dir is created both on the volatile and on the persistent volume, with a bind mount from the former to the latter.

  2. Or a symlink is created on the volatile volume, pointing to the corresponding location on the persistent volume.

Type: one of “bindmount”, “symlink”

Default: "bindmount"

keepTo.<name>.dirs.*.parent.enable

Specify whether the parent dir of this dir shall be configured with custom ownership and permissions.

By default, missing parent dirs are always created with ownership root:root and mode 0755, as described in tmpfiles.d(5).

Ownership and mode may be configured through the options parent.user, parent.group, parent.mode.

Defaults to true when username is not root and the path has a parent dir (is not a top-level path).

Type: boolean

Default: false

keepTo.<name>.hideMount

Whether to hide the bind-mounts of the preserved dirs and files from desktop environments and file managers, by adding the mount options x-gvfs-hide and x-gdu.hide to every bind-mounted entry.

Type: boolean

Default: false

Declared by:

keepTo.<name>.username

Specify the user for which dirs and files are preserved.

The default root configures system-level preservation: paths are interpreted as absolute paths and ownership defaults to root.

When set to any other user, paths are interpreted relative to that user’s home dir (home), and parent dirs on persistent storage are configured with the user’s ownership and permissions.

Multiple entries with different users may be configured side by side, each under its own attribute name (path).

Type: string, not containing newlines or colons

Default: "root"

Example: "alice"
